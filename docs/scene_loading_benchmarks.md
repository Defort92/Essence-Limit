# Бенчмарк переходов между сценами

В debug-сборках `SceneManager` автоматически измеряет каждый переход, в том
числе переход из города в `main.tscn` и обратно. Результаты выводятся в консоль
Godot с префиксом `[SceneBenchmark]`.

## Что измеряется

- `dependencies` — время чтения списка прямых зависимостей сцены и сам список;
- `resource load` — синхронная загрузка `PackedScene` со всеми нужными ресурсами;
- `instantiate/change request` — вызов создания и постановки новой сцены в дерево;
- `target scene ready` — полное время до завершения `_ready()` новой сцены;
- `scene tree` — число узлов и изменение статической памяти;
- `grass ...` — время пересборки каждого grass-MultiMesh:
  - `mask` — получение изображения маски покрытия;
  - `allocate` — создание и выделение буфера `MultiMesh`;
  - `populate` — проверка кандидатов и запись трансформов;
  - `publish` — назначение готового `MultiMesh` узлу;
- `first process frame` и `second frame` — время до следующих кадров после
  готовности сцены;
- `RESULT` — краткая сводка всего перехода.

`cached before=false` означает холодную загрузку ресурса. Для сравнения
производительности нужно сделать несколько переходов в обе стороны: первый
проход обычно дороже из-за файлового кэша, импорта ресурсов и компиляции
шейдеров.

`SceneManager` дополнительно удерживает LRU-кэш трёх последних `PackedScene`.
На повторном маршруте ожидается `cached before=true` и почти нулевое значение
`resource load`. Ограничение в три сцены не позволяет кэшу разрастись до всех
локаций и этажей подземелья.

## Ориентиры

Сводка использует диагностические пороги:

- до 100 мс — `OK`;
- 100–250 мс — `NOTICEABLE`;
- 250–1000 мс — `SLOW`;
- больше 1000 мс — `VERY SLOW`.

Это не требования к релизу, а удобные сигналы для локальной разработки.
Одиночный холодный запуск в редакторе сравнивать с релизной сборкой нельзя.
Для перехода без загрузочного экрана стабильные значения выше 100–150 мс уже
будут заметны игроку.

## Как читать результат для травы

Если основное время находится в `resource load`, причиной могут быть большие
сериализованные буферы MultiMesh и текстуры. Если большое значение находится в
`grass total`, задержка возникает при runtime-пересборке травы. Если обе фазы
дорогие одновременно, сцена, вероятно, загружает сохранённые буферы и затем
сразу заменяет их заново сгенерированными.

Замеры включены только для debug-сборок. В release-сборке `SceneManager`
использует обычный `change_scene_to_file()` без диагностического обхода
зависимостей и подробного логирования.
