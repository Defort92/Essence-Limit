# Требования к текстурам окружения

Этот файл — обязательная художественно-техническая спецификация для создания или
генерации окружения **Essence Limit**. При запросе окружения для города, расовой
локации или этажа подземелья сначала определяется профиль уровня по шаблону ниже,
а затем применяются общие требования этого документа.

Если запрос для конкретного уровня противоречит этому файлу, нельзя молча выбирать
один из вариантов: противоречие нужно обозначить и согласовать исключение.

## 1. Целевой визуальный стиль

- Гибрид настоящих пиксельных персонажей и стилизованного low-poly 3D-окружения.
- Текстуры окружения должны выглядеть нарисованными в низком разрешении, а не как
  фотореалистичные изображения, уменьшенные постфильтром.
- Крупные формы и силуэты важнее мелкого шума. Материал должен читаться с игровой
  изометрической/ортографической камеры.
- Освещение — ступенчатое toon-освещение. Свет и тени не следует подробно запекать
  в albedo, иначе они будут конфликтовать с освещением Godot.
- Общая экранная пикселизация является экспериментальным эффектом, а не способом
  исправить неподходящие исходные текстуры. Исходник должен работать и без неё.

## 2. Разрешение и плотность пикселей

- Размеры исходных текстур — степени двойки: `16`, `32`, `64`, `128` или `256` px.
- Значение по умолчанию для обычного модульного объекта: `32×32` или `64×64`.
- `128×128` допустимо для крупного здания или атласа. `256×256` — только для атласа
  набора объектов либо уникального крупного объекта, которому действительно нужна
  дополнительная читаемость.
- Для одного набора окружения используется единая плотность texel density. Базовый
  ориентир: `16 px` на `1 м`; для важных объектов разрешён профиль `32 px` на `1 м`.
  Профили нельзя случайно смешивать на соседних объектах.
- Один нарисованный пиксель должен оставаться визуально целым. Не использовать
  дробный масштаб UV, размывающее увеличение или искусственный AI-upscale.
- Узор пола и земли обязан бесшовно повторяться. Проверять минимум раскладкой `3×3`.

## 3. Палитра и значения яркости

- У отдельного обычного материала желательно `4–8` основных цветов; у сложного
  уникального объекта — не более `12–16`, если большее число не обосновано.
- Палитра уровня должна быть ограниченной и общей для земли, построек и декора.
  Базовый ориентир — `24–48` значимых цветов на весь набор окружения без учёта VFX.
- Не использовать почти одинаковые оттенки ради шума. Каждый оттенок должен
  описывать форму, материал, износ или важный акцент.
- Соседние грани тёмного объекта должны различаться по яркости. Чёрный материал не
  должен состоять из одного сплошного чёрного значения: нужен холодный или тёплый
  оттенок поверхности и отдельные значения для освещённой и теневой стороны.
- Не полагаться только на экранный контур. Геометрия и albedo должны сохранять
  читаемость при выключенных контурах.
- Самые яркие и насыщенные цвета резервируются для интерактивных объектов, магии,
  опасности и сюжетных акцентов. Фоновое окружение не должно спорить с персонажем.

## 4. Рисунок и детализация

- Использовать чёткие кластеры пикселей, ступенчатые диагонали и намеренные пятна.
- Не использовать фотошум, мелкое зерно на каждом пикселе, сглаженные градиенты,
  размытие, depth of field, JPEG-артефакты и полупрозрачную кайму по краям.
- Износ распределять крупными осмысленными группами: трещины, сколы, мох, пятна.
  Равномерный процедурный шум по всей поверхности запрещён.
- Детали должны соответствовать масштабу мира: трещина, доска или кирпич не должны
  внезапно менять визуальный размер между объектами одного набора.
- Контуры не запекать вокруг каждой детали. Силуэт можно подчеркнуть изменением
  значения/цвета; экранный 3D-контур добавляется отдельно.

## 5. Необходимые карты материала

Минимальный обязательный результат:

1. `albedo` — PNG, без запечённых направленных теней и бликов;
2. `opacity` или альфа-канал — только для листвы, решёток, ткани с прорезями и
   других действительно вырезанных форм.

Дополнительные карты создаются только когда они дают заметную пользу:

- `normal` — слабая, с крупными формами; не превращать каждый пиксель в рельеф;
- `roughness` — ступенчатая, обычно `2–4` уровня серого;
- `emission` — отдельная маска для магии, лавы, рун, окон и других источников света;
- `height`/`displacement` — не генерировать без отдельного запроса.

Metallic используется только для действительно металлических частей. Для камня,
земли, дерева и растительности значение metallic должно быть `0`.

## 6. Прозрачность, растительность и трава

- Прозрачный фон должен иметь чистую альфу без светлой или тёмной каймы.
- Для cutout-текстур используются жёсткие края без anti-aliasing; полупрозрачность
  допустима только когда она является частью эффекта, а не сглаживанием силуэта.
- Трава — отдельный декоративный слой `MultiMesh`, а не часть текстуры земли.
- На траву и тонкую растительность экранные контуры не накладываются: большое число
  контуров создаёт визуальный шум. Их форма читается силуэтом и контрастом палитры.
- Земля под травой обязана выглядеть законченной и при скрытой траве.
- Для каждого биома можно менять цветовой профиль травы, но сохранять общий масштаб
  травинок и согласованность с землёй.

## 7. Контуры и тёмные материалы

- Контуры добавляются шейдером и не должны быть нарисованы в текстуре как постоянная
  чёрная рамка.
- Для крупных твёрдых объектов допустим экранный контур толщиной около `1 px`.
- Для очень тёмных объектов применяется более светлый адаптивный контур, но сама
  текстура всё равно должна разделять плоскости значениями яркости.
- Не применять контуры к траве, мелким листьям, частицам, дыму и мягким VFX.
- Не делать все углубления абсолютно чёрными: оставлять цветовой оттенок и запас
  яркости, чтобы toon-тень не уничтожала детали.

## 8. Импорт в Godot 4

- Фильтрация: `Nearest` / `texture_filter = nearest`.
- Repeat включается только для бесшовных поверхностей.
- Mipmaps для маленьких спрайтов и cutout-растительности обычно выключены. Для
  больших повторяющихся 3D-поверхностей решение принимается после проверки мерцания
  на целевой камере; mipmaps не должны размывать пиксельные кластеры в рабочем плане.
- Компрессия не должна создавать цветные ореолы и грязь в альфа-канале.
- Для атласов оставлять между островами минимум `2 px` защитного отступа в исходном
  разрешении; при mipmaps может потребоваться `4 px`.
- Масштаб модели, UV и размер материала проверяются в тестовой сцене с персонажем,
  а не только в редакторе текстур.

## 9. Что передавать при генерации окружения уровня

Перед генерацией нужно заполнить или явно принять значения по умолчанию:

```text
Название и тип уровня:
Сюжетное настроение:
Основные материалы:
Палитра (5–10 опорных цветов):
Цвет и характер освещения:
Профиль texel density: 16 px/м (обычный) или 32 px/м (детальный)
Модульная сетка и размеры объектов в метрах:
Список необходимых тайлов/объектов:
Какие поверхности должны быть бесшовными:
Какие объекты интерактивны и требуют визуального акцента:
Растительность и цветовой профиль травы:
Нужные карты кроме albedo:
Разрешённые исключения из общих требований:
```

Если данных недостаточно, безопасные значения по умолчанию: `16 px/м`, текстуры
`32×32`/`64×64`, albedo без запечённого света, `4–8` цветов на материал, Nearest,
без normal/height-карт и без нарисованных контуров.

## 10. Комплект результата и проверка

Для каждого набора окружения результат должен включать:

- исходные PNG с понятными именами `<level>_<material>_<variant>_<map>.png`;
- таблицу объектов с размером в метрах и разрешением текстуры;
- палитру уровня отдельным PNG или списком HEX-цветов;
- превью материалов без фильтрации минимум в масштабе `1×` и `4×`;
- для бесшовных материалов — превью повторения `3×3`;
- пометку о сгенерированных, сторонних и вручную изменённых ресурсах;
- тест в Godot рядом с персонажем и при включённых/выключенных toon-контуре и траве.

Набор не считается готовым, если пиксельная сетка между объектами заметно меняется,
тёмные грани сливаются, тайл имеет видимый шов, альфа содержит ореол либо материал
работает только благодаря общему экранному фильтру.
