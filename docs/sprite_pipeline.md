# Пайплайн спрайтов: от генерации ИИ до анимации в игре

Сквозной процесс превращения сгенерированной ИИ картинки персонажа в
покадровую анимацию, которую грузит `DirectionalSprite3D`
([scripts/components/directional_sprite.gd](../scripts/components/directional_sprite.gd)).

```
prompt_gen.py / pixellab_gen.py     генерация промптов / картинок
        │
        ▼
  папка с сырыми PNG                любой размер, зелёный или прозрачный фон,
  (front.png, se.png, north_v2.png) имена = направления (алиасы поддерживаются)
        │
        ▼
prepare_sprites.py  ◄── ЕДИНАЯ КОМАНДА, дальше всё автоматически
        │   1. определение ракурса по имени файла
        │   2. pixel snap (опц.), удаление зелёного фона (автодетект)
        │   3. чистка полупрозрачного мусора (alpha floor)
        │   4. нормализация роста: все ракурсы к одной высоте силуэта
        │   5. канва 128×128, стопы на общей базовой линии y=119
        │   6. зеркалирование недостающих ракурсов (--mirror)
        │   7. проверка согласованности ракурсов  → consistency.txt
        ▼
split_parts.py (вызывается автоматически, можно и отдельно)
        │   8. разрез на части: head / torso / legs_left / legs_right
        │   9. сборка тестовых анимаций idle (дыхание) и walk (заглушка шага)
        │  10. проверки: точность реконструкции, дрейф базовой линии → report.txt
        ▼
  _prepared/
    normalized/<ракурс>.png      готовые статичные 128×128 (замена base/*.png)
    parts/<ракурс>/*.png + parts.json   слои для paper-doll / экипировки
    frames/<ракурс>/idle_NN.png, walk_NN.png   ← раскладка игры
    preview.png                  контрольный лист всех кадров
    report.txt, consistency.txt  результаты проверок
        │
        ▼ (руками, после просмотра preview.png)
assets/sprites/characters/base/frames/   → игра подхватывает без правок кода
```

## Команды

```bash
# полный прогон: сырые генерации → кадры анимации
python tools/prepare_sprites.py <папка_с_сырыми_png> --mirror

# только нормализация, без разрезания (например, для статичных врагов)
python tools/prepare_sprites.py <папка> --no-split

# отдельно разрезание уже нормализованных 128×128
python tools/split_parts.py <папка_с_ракурсами>
```

Зависимости: `pip install -r requirements.txt` (Pillow + numpy уже там).

## Соглашения (важно соблюдать всем инструментам и художникам)

| Параметр | Значение |
|----------|----------|
| Канва кадра | 128×128, прозрачный фон |
| Базовая линия стоп | y = 119 (отступ 8px от низа), одинаковая для ВСЕХ ракурсов и кадров |
| Центр по X | 64, считается по нижней четверти силуэта (стопы), не по bbox |
| Имена ракурсов | `front, front-right, full-right, rear-right, back, rear-left, full-left, front-left` — только дефисы |
| Имена кадров | `idle_01.png … idle_NN.png`, `walk_01.png …` — нумерация с 01, без пропусков |
| Прозрачность | под пикселями с alpha=0 RGB обнулён (никакого скрытого цвета от хромакея) |

Алиасы направлений в именах сырых файлов: `s/south → front`, `n/north → back`,
`se → front-right`, `sw → front-left`, `ne → rear-right`, `nw → rear-left`,
`e/east/right → full-right`, `w/west/left → full-left`. Подчёркивания и
префиксы допустимы: `character_NE_final.png` распознается как `rear-right`.

## Что означают флаги в отчётах

- `INTEGRITY FAIL` (report.txt) — части не пересобираются в оригинал.
  Не бывает при штатной работе; если появился — багрепорт по инструменту.
- `BASELINE DRIFT` (report.txt) — в кадрах анимации гуляет опора: персонаж
  будет «прыгать». Кадры в игру не копировать.
- `HEIGHT OFF` (consistency.txt) — ракурс не дотянут до общего роста, обычно
  из-за запрета апскейла (`--max-upscale 1.0`). Решение: перегенерировать
  ракурс крупнее или разрешить апскейл `--max-upscale 1.3` (лёгкая потеря
  чёткости пикселей).

## Замена заглушки walk на настоящие кадры

Сгенерированный walk — процедурная заглушка (подъём ноги + оседание корпуса).
Когда появятся нарисованные/сгенерированные кадры шага:

1. привести их тем же `prepare_sprites.py` (папка с кадрами одного ракурса
   тоже нормализуется, главное — имена);
2. положить как `frames/<ракурс>/walk_01.png…` поверх заглушки — код игры
   не меняется, `_load_series` подхватит любое количество кадров;
3. прогнать `split_parts.py` не нужно, но проверку дрейфа стоит — она в
   report.txt любого прогона по этой папке.

## Экипировка (задел на будущее)

`parts/<ракурс>/parts.json` хранит координаты разрезов (`head_end`,
`torso_end`, `legs_split_x`) и якорь. Слои предметов рисуются на той же канве
128×128 с тем же якорем и складываются в зеркальное дерево
`equipment/<предмет>/<ракурс>/idle_NN.png` — тогда существующий
`_load_series` читает их без изменений, а `DirectionalSprite3D` потребует
только дочерние Sprite3D-слои, синхронизированные по `_frame_index`.

## Известные ограничения

- Ноги в профильных ракурсах (`full-left/right`) перекрываются — разрез
  идёт по центру масс стоп, подъём ноги в walk выглядит условно.
- Нормализация роста масштабирует NEAREST'ом с дробным коэффициентом:
  для генераций 512+ это незаметно, для готового пиксель-арта 128×128
  лучше подавать кадры уже в целевом размере.
- `--mirror` зеркалит и асимметричные детали (причёску, шрамы) — для
  базового манекена ок, для уникальных персонажей генерировать обе стороны.
